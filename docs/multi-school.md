# 他の学校で使うときの設計

提出版は1校分のダミーで動く。ここに書くのは、他の学校で使うときの設計で、まだ作っていない。実際のテナント、学校、人にはつないでいない。

## 投稿先の差し替え

投稿先は `PostDestination`（`src/lib/destination/types.ts`）の形で決めてある。画面とアプリの処理は `getDestination`（`src/lib/destination/current.ts`）だけから受け取る。

新しい投稿先を足すときは、次の順に進める。

1. `PostDestination` を満たす部品を作る（Teams、別の校内の場など）
2. `getDestination` で学校の設定に応じて選ぶ
3. `src/lib/destination/dummy-teams.test.ts` と同じ確かめ方を、新しい部品にも通す

今の形には、1校の SQLite を読む前提が残っている。チャネルの一覧、投稿の範囲、いいねの数などを外部の API で返すなら、待ち時間と失敗の扱いを足す必要がある（今の `PostDestination` は同期の関数）。

## 学校ごとの分離

- 学校ごとにデータを分ける。投稿、知恵、パートナー、日報、パートナーの記憶、相談室への知らせは、他の学校から読めないようにする
- 案は2つ。学校ごとに DB を分ける（分離が確実で、バックアップも分けられる）か、全部の表に学校の ID を持たせる（運用は楽だが、1か所の書き忘れで漏れる）。小さく始めるなら前者がよい
- Claude に渡す材料も、同じ学校のものだけにする
- 学校を越えてつながる機能は、分離のあとに、本人が選んだ投稿だけを外へ出す形で別に作る

## ログイン

- 今の人物の切り替えは、署名のない Cookie によるデモ用で、実際の学校では使えない
- 学校のアカウントでのシングルサインオンを第一の候補にする。アカウントのない人の扱いは学校ごとに決める
- ログインを入れるときに、人物の切り替えの画面を消す

## 権限

今はコードで決めている役割を、ログインしている人に結び付ける。

| 見られるもの | 誰が |
|---|---|
| Claude との話 | 本人だけ |
| 相談室への知らせ | 相談室の担当と、本人が選んだ先生 |
| 届けた日報と日記 | 本人が項目ごとに選んだ管理職と担任 |
| 教職員だけのチャネル | 教職員 |
| しばらく出さない相手 | 本人だけ |

実際に使う前に、命や安全に関わるときの手順（夜や週末の対応を含む）を、学校で決める。

## 学校ごとに差し替えるもの

- チャネルの一覧、校舎の絵、相談室の開いている時間、外部の相談窓口の案内
- 生徒の写真をパートナーに使うときの同意と権限

## Google Classroom

Teams ではなく Google Classroom を使う学校のために、投稿先の部品として足すことを考えている。

**Classroom で何ができるかは、まだ確かめていない。** 校内のチャネルのような自由な投稿、返信、いいね、タブの中に画面を置くことなど、Teams の前提で作った流れがそのまま使えるとは限らない。公式の資料を読み、試験用の環境で確かめてから設計する。接続は今回作らない。
